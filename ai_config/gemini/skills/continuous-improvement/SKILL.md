# Continuous Improvement Strategy v3.6
## Стратегия непрерывного улучшения приложения

**Цель:** Довести приложение до состояния «почти идеально» через непрерывный цикл обратной связи.

**Зависимости:** Скиллы `dev-agents` и `translate-video`.

**Источник правды об агентах:** `.agents/WORKFLOW.md` + `.agents/*/AGENT.md` (не этот скилл).

**Запуск стратегии:** `make improve` (в `/home/user/translateVideo`).

## 🔑 КЛЮЧЕВЫЕ ПРАВИЛА (обязательны, не нарушаются)

**0. КАЧЕСТВО ВАЖНЕЕ СКОРОСТИ.** Пользователь никогда не просит ускориться. Каждый шаг делается полностью и хорошо, не «достаточно хорошо для галочки». Если на правильное выполнение нужно больше времени — берётся это время. Срезать углы запрещено. Это касается каждого агента, каждой проверки, каждого коммита.

1. **Минимум 5–7 проблем на пользователя за итерацию** — не 3, не 4, а 5–7 из 10 замечаний каждого пользователя должны быть закрыты к концу итерации.

2. **Бэклог Dev агентов не переносится — берётся в текущий раунд.** Если агент предложил улучшение — оно реализуется в рамках текущего раунда (текущих 10 итераций), а не откладывается «на потом». CEO распределяет по итерациям внутри раунда.

3. **Амбициозные задачи не пугают — их декомпозируют.** WebSocket, авторизация, совместный доступ, Redux-хранилище — всё берётся, если пользователи просят. Крупные фичи размазываются по нескольким итерациям (Iteration N: фундамент → Iteration N+1: логика → Iteration N+2: UX).

4. **Вопросы паркуются, задаются после раунда.** Если в процессе возникают неопределённости (формат данных, бизнес-требование, выбор технологии) — принимается лучшее инженерное решение, вопрос фиксируется в разделе `## 🅿️ Припаркованные вопросы` и задаётся пользователю после завершения всех итераций раунда.

5. **Каждая итерация = деплой в прод.** Никаких «почти готово» без `make deploy` + `make verify:deployed`. Проверка: `curl http://localhost:8002/api/health` — версия должна совпадать с `cat VERSION`.

14. **Порядок итерации:** `make iteration` = тесты + деплой + верификация + **4 агента АВТОМАТИЧЕСКИ** (QA Monitor, Designer, Tech Writer, Skill Modernizer). `make round-close` = 8 стратегических агентов (CEO, CTO, PM...) + push. Схема: `make iteration` → `make round-close` (8 стратег.) → `git push origin develop`. **4 code-quality агента НЕ НУЖНО вызывать вручную** — они встроены в make iteration.

   18. **НЕ СПРАШИВАТЬ разрешения между итерациями — делать.** Запрещено писать «Продолжаем?», «Начинаем И2?» без причины. Однако: если в процессе итерации обнаружена проблема требующая осмысления — остановиться, разобраться, решить правильно. Скорость не оправдывает некачественное решение. Допустимо остановиться и спросить пользователя если без его ответа невозможно принять качественное решение (архитектурный выбор, неоднозначное требование).

   19. **АГЕНТЫ — ОБЯЗАТЕЛЬНЫ, не опциональны.** После `make round-close` ОБЯЗАТЕЛЬНО запустить всех 8 стратегических агентов: CEO, CTO, PM, QA-Engineer, UX-Designer, ML-Engineer, Business-Analyst, System-Analyst. Каждый агент ДОЛЖЕН записать реальный review в `.agents/{role}/review-log.md` с подписью `### Подпись: {Role} АПРУV | YYYY-MM-DD vX.Y.Z`. Заменять агентов сводной таблицей или комментарием — ЗАПРЕЩЕНО. Агенты — это не форматирование отчёта, это отдельный аналитический шаг с реальными замечаниями и бэклогом для следующего раунда.

15. **`make round-close v4.0` — единственный честный gate.** Нельзя подделать: [1] Python unittest запускается сам, [2] tsc --noEmit, [3] grep security в src/, [4] docker + версия прод=локально, [5] git log AGENT.md, [6] HTTP smoke SRT+DOCX=200, [7] RELEASE_NOTES + roadmap версия, [8] user-surveys/*.md с персонами. Писать АПРУV в лог без запуска команд = нарушение.

16. **D-RULE-02: после каждого `make deploy` → chown.** `docker exec --user root video-translator chown -R appuser:appuser /app/runs/` — без этого SRT/DOCX экспорт вернёт PermissionError 500. Встроено в Makefile deploy, но проверять вручную если deploy запускался нестандартно.

17. **Опрос пользователей — обязательная проверка раунда.** Business Analyst обязан создать `user-surveys/R{N}-survey.md` с минимум 3 персонами и их реальными инсайтами. round-close [8] блокирует push если файла нет. Инсайты из опросов → P1 в user-stories.md.

6. **1019 тестов — текущая планка.** *(1017 до v1.98.9)* *(981 до v1.98.8)* *(958 до v1.98.4)* *(932 до И3-И5, 920 до R13, 887 до R11, 832 до R9)* *(920 до R13, 887 до R11, 832 до R9, 827 до R5)* Не снижаем. Новые фичи = новые тесты. *(887 до Round 11, 832 до Round 9, 827 до Round 5, 590 до Round 3)*

11. **Новый роутер/endpoint — тесты сразу, в той же итерации.** Если создаётся новый файл `routes/X.py` — минимум 5 unit-тестов для него пишутся в той же итерации. Не в И5 «QA Gate», а сразу. Analytics.py: 51% coverage обнаружена только на И5 — это нарушение.

12. **Designer: перед навигационной проверкой — grep LS_KEY в OnboardingTour.tsx.** Неправильный ключ localStorage блокирует всю визуальную проверку. Команда: `grep -n 'LS_KEY\|localStorage.setItem' ui/src/components/OnboardingTour.tsx | head -5`.

13. **Агенты запускаются ДО merge в develop, не после.** WORKFLOW.md Правило 2 — апруv Designer + QA Monitor + Tech Writer + Skill Modernizer ОБЯЗАТЕЛЕН перед каждым `git merge --no-ff ... develop`. Нарушение = работа проделана зря (может откатиться).

7. **TypeScript ошибки — проверяй `ui/src/types/schemas.ts` первым делом.** Большинство TS-багов при сборке — несоответствие полей (например `ended_at` vs `finished_at` в `StageRun`).

8. **JSX-структура: проверяй вложенность div при любом изменении разметки.** Нарушение иерархии ломает рендер без очевидной ошибки. Особенно опасно вставлять блоки между `card-header` и `card-body`.

9. **Rate limiter — всегда exemptить localhost/testclient немедленно.** Если пишешь in-memory rate limiter — сразу добавляй исключение для `127.0.0.1`, `::1`, `testclient`, `""`. Иначе тесты упадут после 5-го запроса к одному endpoint'у.

10. **Каждая итерация — отдельный коммит.** Не объединять итерации ради скорости. Атомарные коммиты позволяют точно откатить изменения и ясно отследить что было сделано в каждой итерации.

## Агент обратной связи (FBA)

**Обязанности:**
1. Генерировать 5 случайных профилей (разные возраст, соц. слой, устройства)
2. Каждый пользователь → **10 замечаний** (не 12, чтобы фокусироваться)
3. Агрегировать → CEO-отчёт с весами
4. После реализации — собирать dev-отчёты, фиксировать закрытые/открытые проблемы

**Правила когорты:**
- Никаких повторяющихся профилей между итерациями
- Минимум 1 человек с низкой технической грамотностью (1-2)
- Минимум 1 человек старше 55 лет
- Минимум 1 мобильный пользователь

**Формат замечаний (10 штук на пользователя):**
```
Критические (4): блокируют использование
Мажор (3): раздражают, снижают ценность
Минор (3): было бы хорошо
```

## Алгоритм одной итерации

> ### 🔴 ОБЯЗАТЕЛЬНЫЙ ПРОТОКОЛ ЧТЕНИЯ АГЕНТОВ
> **Перед тем как действовать от имени любого агента — прочитать его AGENT.md:**
> ```bash
> # Универсальная команда:
> cat .agents/{role}/AGENT.md
> # Также — дистиллят последних уроков:
> cat .agents/LESSONS.md
> ```
> **Без чтения AGENT.md = агент работает вслепую, игнорируя накопленный опыт.**
> Это нарушение принципа «каждый агент — лучшая версия себя после каждого раунда».

```
1. Читать: cat .agents/business-analyst/AGENT.md  ← ОБЯЗАТЕЛЬНО

3. Каждый проходит приложение → 10 замечаний
4. FBA агрегирует 50 замечаний → структурированный отчёт CEO
```

### Фаза 2 — CEO: стратегия
```
0. Читать: cat .agents/ceo/AGENT.md  ← ОБЯЗАТЕЛЬНО
1. Читает FBA-отчёт

3. Крупные задачи декомпозирует на подзадачи по итерациям раунда
4. Предложения Dev агентов прошлой итерации — БЕРЁТ В ТЕКУЩИЙ РАУНД

```

## Критерии перехода

| Условие | Действие |
|---------|---------|
| ≥ 5 проблем каждого пользователя закрыты | Переход к следующей итерации |
| Тестов меньше, чем было | **QA Monitor** блокирует деплой |
| Coverage < 80% | **QA Monitor** блокирует деплой |
| Build failed | **DevOps** блокирует деплой |
| Changelog не обновлён | **Tech Writer** блокирует следующую итерацию |
| Критический UX-баг (Designer) | Исправить **немедленно**, не переходить |
| Skill Modernizer нашёл антипаттерн | Обновить скилл **немедленно**, применить в итерации |
| Крупная фича не влезла в итерацию | Фиксируем прогресс, продолжаем в следующей |
| Все итерации раунда завершены | Задаём припаркованные вопросы пользователю |
